# update —— 里程碑更新（最常用）

> 触发：完成了一个功能/阶段、修完一批问题、用户说"更新一下仪表盘"，或日常开发告一段落。

1. **采集事实**：`<Python解释器> <skill目录>/scripts/collect_facts.py dev-dashboard/`（两处占位符都替换成实际路径）。
2. **逐条归置** .facts.json 里的每条事实（一条都不许漏）：
   - 与某功能相关 → 更新 FEATURES.md：补证据路径、改状态（AI 上限「可用」）、修订简介；
   - 值得让用户知道 → NOW.md 时间线**顶部**加一条人话（"做成了什么、对你意味着什么"），带证据路径；
   - 用户指令式状态变更（"把「X」标为进行中 / 废弃「X」 / 恢复为设想"，常由仪表盘详情窗的「生成指令」按钮带来）→ 按用户说的改 FEATURES.md 状态，时间线记一笔人话；
   - 纯内部工程（重构、依赖升级、CI、格式化）→ 追加到 `.dashboard-ignore`；
   - 文件被删除（`.facts.json` 里 `change` 为 `deleted`）→ 时间线记一笔人话，或在 `.dashboard-ignore` 里说明；删除事件同样必须归置，不能不管；
   - 拿不准 → 问用户，或在时间线标 [待确认: 这是什么改动]。
3. **检查状态机**：本阶段做完的功能标「可用」并在 NOW.md 待办加"试用某功能"；等用户验证。
4. **发现需要拍板的事** → NOW.md 新增决策卡（D 编号递增），并立即用原生选项卡向用户提问（HTML 里的复制按钮是兜底）。
5. **渲染**：`<Python解释器> <skill目录>/scripts/render_dashboard.py dev-dashboard/`；退出码 2 = 有 BLOCKER（证据失效或越界 / 「已验证」缺验证记录 / 事实未归置），当场修到 0。
6. **一句话收尾**：这次收录了几条变更、哪些功能状态变了、有没有等他拍板的事。
