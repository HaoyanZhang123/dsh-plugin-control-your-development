# v1.0.0-alpha.1 · 脉络 / Threadline 首个 alpha

## 中文

这是「脉络 / Threadline」的第一个 alpha 预览版：它把这个插件从「人工维护 Markdown 的产品仪表盘」整体重构为**永久只读的工作区可视化**，旧面板实现与整条构建链已全部移除。

**变更概览**：新增 9 项 · 优化 2 项 · 修复 3 项

**新增**

- 工作区星图：只画 DSH 真正触碰过的文件，按目录分簇；节点大小跟随操作次数，颜色跟随文件族。
- 四层关系：结构、共现（同一轮 / 同一会话）、引用（解析文件正文所得）、时序（同一轮内先后）；共现不会被称为依赖，未确认引用只列出、不画边。
- 轮次带：每一轮的状态、时长与文件 / 命令 / 错误 / 子智能体标记；仍在记录的那一轮会明确标注。
- 三种检查器：文件、轮次、会话，每个数字都能看到对应的记录证据，含「后续触碰」与「与上一轮对比」。
- `/threadline` 命令：把一段对话重建成 起点 → 轮次轨迹 → 终点，并列出它产出的文件与仍未闭环的事项。
- 每轮影响：已定稿助手消息下方的一个图标，打开即该轮影响，可跳进完整脉络。
- 隐私模式：默认只显示元数据；开启后路径只显示文件名、命令只显示程序名、会话标题改为编号。
- 列表视图：同一份数据的文件表与轮次表，键盘可达、读屏可读。
- 工作区预热：插件加载即开始扫描并持续增量更新，打开脉络 tab 时数据已经就绪。

**优化**

- 三个入口共用同一份数据与选择状态，切换 tab / 弹窗 / 图标不重复加载。
- 载入与失败都如实呈现：未加载、读取失败、观测不到、按参数估算分别标注，不用 0 或空态冒充未知。

**修复**

- 弹窗与影响浮层改为挂载到页面根节点，修复在 DSH 0.2.2 下被输入框容器裁切导致的错位。
- 修复「不先打开 tab 就读不到数据」：现在直接按 `/threadline` 或点影响图标也能读取。
- 修复图标在数据未读全时静默消失的问题，改为显示「本轮仍在记录」。

**重要说明**

- 这是 alpha 预览版，界面与数据模型仍可能调整；预发布版本发布在 npm 的 `alpha` 标签下，不影响 `latest`。
- **破坏性变更**：0.7.x 的五个 tab、Markdown 事实源、`.view.json` 读模型、Python 渲染器、运行控制与离线导出全部移除，不提供迁移路径；旧版本请继续使用 0.7.x。
- 插件**永久只读**：不写工作区、不写会话日志、不改设置、不调用模型、不发出任何外部请求，也没有任何运行控制按钮。
- DSH 已安装插件不会自动更新，升级 = 卸载后重装。

## English

The first alpha preview of **Threadline**: the plugin has been rebuilt from a hand-maintained Markdown product dashboard into a **permanently read-only visual map of a DSH workspace**. The old panel implementation and its whole build chain are gone.

**Summary**: Added 9 · Improved 2 · Fixed 3

**Added**

- Workspace star map: only files DSH actually touched, clustered by directory; node size follows operation count, colour follows file family.
- Four relation layers: structure, co-occurrence (same turn / same conversation), reference (parsed from file text) and sequence (order within one turn). Co-occurrence is never called a dependency, and unconfirmed references are listed rather than drawn.
- Turn strip: status, duration and file / command / error / subagent markers per turn, with the still-recording turn labelled as such.
- Three inspectors: file, turn and session, each showing the recorded evidence behind a number, plus later touches and a comparison with the previous turn.
- `/threadline` command: rebuilds one conversation as start → turn trail → end, listing the files it produced and what is still open.
- Per-turn impact: one icon under each finished assistant message, opening that turn's impact and jumping into the full map.
- Privacy mode: metadata only by default; when enabled, paths show basenames, commands show program names and session titles become numbers.
- List view: the same data as keyboard-navigable file and turn tables.
- Workspace warm-up: scanning starts as soon as the plugin loads and keeps updating, so the tab is already populated when opened.

**Improved**

- The three entries share one data set and one selection state; switching tab, dialog or icon does not reload anything.
- Loading and failure are shown honestly: not loaded, failed to read, not observed and estimated are labelled separately, and never replaced by `0` or an empty state.

**Fixed**

- The dialog and the impact popover now mount at the page root, fixing misplacement caused by the composer container clipping them under DSH 0.2.2.
- Fixed "no data until the tab has been opened": `/threadline` and the impact icon now read data on their own.
- Fixed the impact icon silently disappearing while data was still incomplete; it now shows "this turn is still recording".

**Important Notes**

- This is an alpha preview; the interface and data model may still change. Prereleases are published under the npm `alpha` tag and do not touch `latest`.
- **Breaking change**: the five-tab panel, Markdown source of truth, `.view.json` read model, Python renderer, run controls and offline export are all removed with no migration path. Please stay on 0.7.x if you need them.
- The plugin is **permanently read-only**: it writes no workspace files, no session logs and no settings, calls no model, makes no outbound request, and exposes no control actions.
- Installed DSH plugins do not update automatically; upgrading means uninstalling and reinstalling.
