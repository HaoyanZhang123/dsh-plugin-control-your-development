# v0.6.1 — Evidence paths no longer overflow a narrow sidebar · Paths no longer vanish when printing

> In one line: when the right sidebar was narrowed, the evidence path pill used to **push the whole row past the card's right edge** and shove the copy button outside it. This release fixes that — in a narrow column the path is **truncated on a single line** (hover for the full text), the **copy button is never clipped**, and the panel and the offline page now **look the same**; print/PDF restores wrapping so paths are printed in full.
> It also fixes a **pre-existing defect**: the print-hidden rule used to hide the **"click anywhere to copy" path pill** along with the copy button, so **143 evidence paths disappeared entirely** from paper. The rule is now narrowed to the copy button only.

## ✨ What this release fixes

### 1｜Evidence rows no longer overflow the card in a narrow sidebar

- What you reported: dragging the right sidebar narrow made the evidence path pill **jump past the card's right border**, with the **copy button pushed outside the box** (measured: at a `364px` container the worst overflow was **68.8px**, and all 3 copy buttons were outside);
- The cause is two things that only show up together:
  - The **panel branch** renders evidence as `button.btn.mini`, which inherits `.btn{white-space:nowrap}` ⇒ the pill's **minimum width equals the entire path**, and `.evrow` is `inline-flex` whose children have `min-width:auto`, so they **cannot shrink**;
  - The **offline branch** renders `<a>` (no `nowrap`), which **wraps automatically** ⇒ **only the panel overflowed** — which is exactly why every gate was green and still missed it;
- Behaviour now (the decision you confirmed):
  - The path is **truncated on one line**, ending in `…`; **hover the `title` for the full path** (the `title` is always the complete text, never shortened);
  - The **copy button is always there and never clipped** (`flex:none`) — the path may shrink to a bare `…`, but the copy action never disappears;
  - The **panel and the offline page look the same** (they share one render core);
  - Under print/PDF the path **wraps again** instead of being cut off.

### 2｜Printing no longer swallows evidence paths (pre-existing defect)

- The print-hidden rule used to be `.btn[data-cp]` — but `data-cp` does **not** only sit on the copy button: the **branch ④ path pill** (used when there is no open action and the file exists, i.e. "the whole pill is the copy button") **carries `data-cp` itself**;
- The consequence: **143 path pills were hidden entirely when printing**, so evidence paths simply vanished from paper;
- The rule is now narrowed to the copy button's **dedicated class `.evcp`**: on paper, **hidden path pills went 143 → 0**, while the copy button is still hidden (it only exists to serve on-screen copying);
- The `data-cp` **attribute is left untouched** — clicking to copy still relies on it; only the **print selector** changed.

## ✅ Quality and compatibility

- **Static gates** (run locally): `tools/lint_skill.py --all`, `tools/contract_check.py --all` and `tools/verify_all.py` all pass (17/17); `smoke/run_all_checks.py` reports **14/14 passing**;
- **Cross-language diff**: `smoke/dual_parser_diff.py` — **67/67 identical** (this release does not touch the data contract, so the diff is the same as the previous version);
- **10 new real-machine assertions** in `cdp_verify.mjs` (87 items in total):
  - `④c`, six of them: no geometric overflow; **shrink direction** (path pill `flex-shrink=1` / copy button `0` — the **only** signal that separates "genuinely truncated" from "the whole row is locked", since a locked row can also look like 0 overflow); **truncation actually happening** (`.evtxt`'s `scrollWidth > clientWidth` — text with `display:inline` paints outside its own box, so **geometry assertions cannot see it**; only this check catches it); visibility filtering; plus a fixture guard and a copy-button existence assertion that prevents an "empty-set tautology";
  - `④d`, four of them: **print media** — branch ④'s path pill is visible with wrapping restored, the copy button is hidden, and a self-check that the media was **switched back to `screen`** after measuring;
- **A gate gap closed along the way**: `cdp_verify.mjs` is now covered by the JS syntax gate (`JS_SYNTAX_FILES` **5 → 6** files). Stated honestly, it is a "**cheap extra net**" — it catches an extra backtick inside a template string, but it does **not** catch a bracket mismatch that still leaves the outer text valid JS;
- **Both sides of the assertions themselves** (changing a verification tool requires self-auditing it): the forward direction is fully green; feeding known-bad input in reverse (reverting the print selector to `.btn[data-cp]`, removing the `.evcp` class, injecting `display:inline`) **must genuinely go red and name the specific assertion**;
- ⚠️ **Verification boundary (stated plainly)**: **the user has verified this on their own machine in the real UI** — in a narrow sidebar the evidence path no longer overflows the card and the copy button stays inside it (**verified by eye, by a human**); **the automated real-machine assertions (`--cdp`, 10 new items this round) have still not been run** — these two are not the same thing, so do not read this as "verified on a real machine". The former is the **strongest single piece of evidence** this round, but what it shows is that "the two symptoms the user reported are gone", not that the assertion suite itself has run. The `--cdp` run was blocked by the environment lacking a `DSH_WEB_TOKEN` (`cdp_verify.mjs` currently reports `ABORT`, which is not green). The 10 new assertions above were only checked with an **offline/synthetic harness** — the **real render core plus the real CSS** driven in a real browser for geometry and print media — but **a real-machine `--cdp` run remains unverified**; unverified is not written up as verified;
