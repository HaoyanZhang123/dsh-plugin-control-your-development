# v0.6.0 — Tech map ("Features | Tech" switch) · Change rules · The map now says "this part is out of date"

> In one line: the Feature Map answers "how far along is it?"; this release adds a **Tech Map** that answers "how is it actually built?" — a second view inside the same tab, with modules laid out by layer and dependencies drawn as edges. `TECH.md` (tech map) and `CHANGES.md` (change rules) now get a first draft the moment the dashboard is created, and the map speaks up about **what has gone stale** (evidence that can no longer be found, evidence files deleted and possibly moved, a dashboard written by a newer plugin).
> It also fixes something you reported twice: **the host input box no longer takes up space in the full-page Feature Map** (with three exceptions kept: a pending approval, a pending question, or a plan awaiting review).

## ✨ What you can do in this release

### 1｜A "Features | Tech" switch in the Feature Map toolbar — the tech view shows how it is built

- The toolbar of the full-page **Feature Map** (top of the conversation page) now carries a **Features | Tech** switch. **No new tab** — the number and order of tabs in the navigation are unchanged;
- Switch to **Tech**: modules are laid out vertically by their `层` (layer) — **layer order follows the order in which you first mention them; there is no hard-coded list of layer names** — and modules are connected by the dependency edges declared in `连到`;
- When `连到` points at a module that does not exist yet, the map **does not pretend it does**: the edge becomes a broken stub with a hollow ring, labelled with what is missing (several missing targets from the same module collapse into one label, e.g. "缺 不存在的模块 等 2 个");
- Every module carries seven fields: `模块 / 层 / 职责 / 技术 / 状态 / 证据 / 连到` (with `### 子项` sub-items supported);
- When there is no `TECH.md` yet, the **Tech button is still there** (its tooltip reads "还没有技术地图，点开看怎么建"), and the empty state offers a one-click "建立技术地图" — sent straight into your main conversation from the panel, copied in the offline page.

### 2｜Tech map and change rules are created by default

- Alongside PRODUCT / FEATURES / NOW and the glossary, `init` now **also creates first drafts of `TECH.md` (tech map) and `CHANGES.md` (change rules)** — modules are derived from your features and their evidence paths, and the change rules group each feature's evidence into entries by directory;
- **Nothing is invented**: entries that cannot be derived are left as a `[待确认: 这条改动怎么归置]` placeholder, and you are told: "变更规则和技术地图我也一并建了初稿，它们是从现有证据推出来的，请过一眼";
- Filenames are still yours to choose: `TECH.md` / `tech.md` / `技术地图.md` and `CHANGES.md` / `changes.md` / `变更规则.md` are all recognised (structure matters, not the name);
- A module's **evidence follows the same red line as feature evidence**: paths must really exist and must be accounted for; files declared *only* by the tech map or the change rules are listed **separately** in the audit (with a reminder above 10), so a declaration file nobody reads cannot hide changes.

### 3｜The map speaks up when a part is out of date (stale / moved)

- **Stale**: compared with the tech map in the most recent version snapshot, a module whose evidence can no longer be found **at all** gets a `⚠` next to the tech-view title (and the same sentence under the legend and in the audit layer): `技术地图里有 N 个模块的证据找不到了：X。` / `这份地图可能已经跟不上代码了。` / `去技术地图里把这几条证据改对。` — **the map looks fine while being wrong**, which is exactly when it must say so;
- **Moved**: files deleted in this round's collection that happen to be evidence of a tech-map module (or of a feature / journey / timeline entry) raise "证据文件已被删除（可能搬迁）" — you confirm whether it moved or is really gone;
- Both signals are **fail-closed**: with no previous snapshot, or no match, they produce **nothing** — no permanently-screaming false alarm.

### 4｜When the dashboard is newer than the plugin, it says so instead of silently misreading

`dev-dashboard/.cyd.json` records *who* wrote this dashboard and *which format version* it used. If it came from a **newer plugin or skill** (format ahead of this build, or a writer version newer than the installed plugin), both the panel and the offline page show the same three lines:

> `.cyd.json 是更新版插件写的，当前版本读不全。` / `所以这次不改它，免得把新内容写坏。` / `升级插件后再看就行。`

In that case the file is **read-only** — an older build never rewrites newer data. The sibling case (a format version that is not a number) has its own message whose next step is "set it back to a number", so the two are never merged into one confusing line.

### 5｜No extra input box in the full-page Feature Map

- Opening the full-page Feature Map inside the conversation no longer leaves the host's composer seat visible; **it is kept when there is a pending approval / question / plan review** — otherwise you would face "an approval to type, with no input box";
- The host's width-drag handle is hidden too: it sits in the middle of the map, so a horizontal drag there used to resize the conversation column instead of panning the map;
- ⚠️ **Stated premise**: this relies on **two internal host DOM attribute names** (`data-conversation-scroll` / `data-composer-seat`) — **not an official API**. If the host renames them, it stops working, and **the failure mode is safe**: the input box simply reappears, you can always type. The same coupling is already carried in production by a third-party plugin (`dsh-context`);
- ⚠️ One half of this is **static evidence only**: that third-party plugin also has no input box in its own "编队" view — we read its CSS source plus our own real-machine comparison, **not a side-by-side real-machine comparison of two views in one instance** (the desktop profile is exclusive to Electron; the "编队" view is not visible in a web instance).

### 6｜No more edge labels sitting on top of the graph

Relationship names are no longer rendered as visible text across the middle of the graph (a cleaner map) — but the names are **not lost**: hovering an edge still shows it, and every edge still carries its own relationship name. The switch bar now also hugs its two buttons (asserted in the full-page view and in the sidebar panel separately).

## ⬆️ Upgrading

DSH → Plugins → enter `dsh-plugin-control-your-development` (you can also pin a version: `dsh-plugin-control-your-development@0.6.0`) → **refresh the page (Ctrl+R) or restart DSH**.
The bundled skill (v1.6.0) updates with the plugin — no manual step.
